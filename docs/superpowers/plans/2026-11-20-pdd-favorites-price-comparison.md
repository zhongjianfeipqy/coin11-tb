# 拼多多收藏商品规格比价实施计划

**目标**：从安卓拼多多的收藏商品按店铺采集规格券前价，生成按运行开始时间命名的明细或比价 Excel。

**结构**：`pdd_app.py` 负责操作 App 和读取数据。`pdd_compare.py` 判断店铺归属、保存配对关系并生成明细和差价。`pdd_price.py` 提供终端入口，协调采集、配对和 Excel 导出。

**技术栈**：Python、ADB、`uiautomator2`、`openpyxl`。

**设计**：[拼多多收藏商品规格比价](../specs/2026-11-20-pdd-favorites-price-comparison-design.md)

## 约束

- 「我的收藏 → 商品」是采集范围的唯一来源。按列表店铺分组，复用登录态，使用同一轮中明确对应所选规格的 App 券前价，跳过抢光规格。
- 保持当前分支和已有暂存改动，使用独立脚本。实机验证由用户明确提出后执行。
- 首版由终端手动发起，提供按店铺采集明细、商品和规格配对以及 Excel 导出。

## 任务一：配对与差价表

- [ ] 在 `pdd_compare.py` 定义 `Product`（店名、标题、规格采集结果、问题、跨次配对所需的 ID），`Quote`（完整规格、`Decimal` 券前价、采集时间、状态及原因）和 `Pair`（自家商品 ID、对手商品 ID、手动规格配对）。原始规格以「规格项、选项」的有序集合表达。
- [ ] 按店铺名判断归属。「大飞体育用品数码店」归为自家，其他已确认名称的店铺归为竞品，读不到店名标记为店铺未确认。明细保留店铺名、商品名称、关键名称、券前价、状态和原因。关键名称提取品牌、型号和球速，例如「Victor NO.1号 76速」。
- [ ] 实现 `read_pairs(path) -> list[Pair]` 与 `save_pairs(path, pairs) -> None`。按商品 ID 对维护关系，配对文件不存在时视为首次运行。损坏或冲突时报告原因，更新时原子替换文件。
- [ ] 实现 `comparison_rows(products, pairs, *, scan_complete) -> list[dict[str, str]]`。先匹配手动确认的规格，再按全半角和空白归一化后的完整规格唯一匹配。用 `Decimal` 计算自家减对手，按差价降序排列。跳过已抢光的规格。未配对、价格不明、规格歧义、映射失效和缺少商品按原因出行。区分收藏里缺少商品和采集提前停止。
- [ ] 将明细或差价按固定列序写入 Excel。价格和差价保存为数值，源自 App 的文本保持为文本。检查表头、价格和空白差价分支。

## 任务二：App 取样与采集

- [ ] 使用 ADB 发现已登录的安卓设备。对子智能体开放取样任务，记录收藏页列表边界、店铺标题与商品行的分组、规格弹层的返回路径、选项状态及对应所选组合的券前价节点。另取跨次配对所需的稳定商品标识。原始页面文件保留在临时目录。
- [ ] 在 `pdd_app.py` 从收藏页读取店铺分组，按店铺、商品先后处理，直接点击商品行内的规格名称进入弹层。单轮明细直接保留列表中商品的店铺归属，跨轮同款配对使用稳定商品 ID。设备选择沿用 `uiautomator2` 的设备发现。
- [ ] 逐个确认完整可售规格组合，读取绑定到组合的券前价。明确已抢光的组合只标记缺货供比价时过滤。可售组合读不到明确券前价时记录原因。单商品失败只有在确认回到收藏页后才继续。设备断开或导航状态不明时抛出带原因的采集错误，保留此前已产生的 `Product`。

## 任务三：终端入口与交付

- [ ] 在 `pdd_price.py` 实现 `main(argv=None) -> int`。`pair` 命令从收藏列出店名及标题，按终端编号新增、更正或解除商品配对。对已经配对的商品，可读取当前规格并从完整组合中手动确认或移除规格对应。
- [ ] `scan` 命令输出当次店铺及规格明细，`scan --limit 2` 采集前两家店铺的全部收藏商品。`compare` 命令读取已有配对，重新采集券前价并输出差价表。采集提前停止时保留已读结果并报告原因和数量。
- [ ] `scan` 和 `compare` 每次运行以本地开始时间命名，文件格式为 `YYYY-MM-DD_HH-mm-ss-微秒.xlsx`，工作表分别为「规格明细」和「差价」。默认保存到项目的 `downloads/`，支持 `--output-dir DIR` 改目录。`pair` 只更新用户配置目录里的配对文件。
- [ ] 在 `README.md` 加入安卓连接、小样采集、首次配对和 Excel 导出的用法。说明 App 采集模块接入后的运行条件、券前价口径、差价方向和问题状态。
- [ ] 用户明确要求实机验证后，用一组两边均已收藏、具有多种规格的同款核对券前价和差价。再次采集确认配对可复用，检查已抢光规格是否跳过，以及只有价格区间、规格同名冲突、收藏移除及扫描中断的结果。
